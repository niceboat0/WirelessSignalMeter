## 统一任务

`SurveyTaskStore` 使用独立的 `survey_tasks.db`，保存 UUID 任务、名称、
起止时间、进程时钟域、事件和已有采集 Mission ID 的对应关系。

- 路测、测速、信令页共用任务栏，可新建、结束任务。
- 未结束的任务在切页、进程重启后仍保留；任务不是 Activity 生命周期。
- 全新数据库首次观测可自动建任务。手动结束后，普通观测不会自行重新开启；
  明确开始测速、采集 Mission 或重新开启记录可以建任务。
- 新建任务会结束上一任务。已在执行的测速保留启动时捕获的任务 ID，
  后续结果、失败、取消仍归原任务；结束任务不等于取消在途业务。
- 地图打点保存 task_id、mission_id、subscription_id、SIM 槽、单调时间、
  clock_id，以及定位龄期、精度、provider。
- 测速历史保存 task_id。Android LTE SINR 诊断样本在采样时捕获任务/时钟域；
  不改变 SINR 的来源优先级、有效值规则或单位。
- DIAG 原记录在接收时标记任务、接收时间和采集器批次。衍生记录保留其原记录
  的任务归属。早于新任务边界的缓存包保持未归属，不按导出时的当前任务补填。
- 原有 protobuf 采集文件继续使用其 Mission ID。任务元数据提供 Mission 对应
  和任务时间范围，未修改上游 protobuf 协议；同一 Mission 可跨多个手动任务。

打点数据库 v1/v2 → v3、测速数据库 v1 → v2 使用新增列迁移。
旧行的任务保持未知，不删除历史，也不按时间猜测旧行属于哪个新任务。
任务/事件数据不做隐式清理；界面及导出有读取窗口限制。

## 事件覆盖与含义

| 来源 | 记录内容 | 边界 |
| --- | --- | --- |
| Android 公共 API | 同订阅服务小区/制式/PLMN 变化，保留前后 CID、PCI、频点 | 标为“观测”；不是切换成功、重选成功或掉话证明 |
| Root DIAG | 既有 RRC 派生事件、小区变化、NAS 释放、NAS/IMS 状态变化 | 依赖现有解码能力；没有新增猜测二进制布局 |
| RRC 完成消息 | Setup/Resume/Reconfiguration/Reestablishment Complete、securityModeFailure | 是消息观测，不把单条 Complete 当作完整切换流程统计 |
| 测速 | 开始、逐次完成、失败、取消 | 标明默认网络路由，不宣称绑定某张 SIM |
| 任务 | 开始、结束 | 任务结束后仍可能收到归原任务的在途业务结果 |

Android 观测基线按订阅隔离，任务、时钟域、记录开关代次变化以及超过 30 秒
的缺口会重新建立基线；未知字段变成已知不单独制造小区变化。
无定位仍可保存变化事件。当前只覆盖已有 LTE/NR 服务快照选择器能提供的观测；
不会虚构无服务/重连、2G/3G 或 NSA 辅载波的完整状态机。

RRC 派生事件可关联前一条同 RAT、同消息名、同任务、1 秒以内的原消息，
补入采集批次、消息 ID、事务号、PCI/ARFCN、原因和解码可信度。
原始源时间保留。新鲜源时间用其与接收时钟的差值校正到单调时间；
超出 10 秒或推测数据不自动绑定小区位置。

## 时间线与地图

工具 → 路测覆盖：选择回放任务，再打开“事件”。
时间线按 Android、DIAG、测速、任务过滤；点击已定位事件切换相应轨迹、
样本和地图视野。地图事件标记反向打开时间线并选中对应事件。
同一点有多个事件时可在时间线分别查看。

- 只在同一 task_id 内关联。
- 有进程时钟域时只比较同域单调时间，避免跨重启误配；旧格式才回退墙上时间。
- 关联窗口为前后 10 秒，已知定位龄期不得超过 10 秒，
  已知精度不得差于 100 米；未知精度保留未知显示。
- 有订阅/SIM 的事件必须匹配该来源以及已知 RAT/PCI/频点。
- DIAG 没有可靠的 Android 订阅编号时，需要完整小区标识匹配，
  并且候选只属于一个来源；双卡歧义保持“未关联位置”。
- 测速只关联附近设备位置，不分配网络订阅。双卡候选位置相差超过 30 米时
  不互换位置；界面明确显示“设备位置 / 网络归属未知”。
- “附近打点”是有时间差的匹配位置，不冒充事件瞬间的精确 GPS。
- 时间线打开期间响应新事件更新打点快照，保留当前选择。

轨迹按任务和订阅分组，时钟域变化或超过原有 120 秒缺口会分段。
一次读取最多 50,000 个最近打点、每任务 10,000 个最近事件；任务选择最近 200 项。
地图最多渲染最近 1,000 个不同事件样本位置，并保留当前选中标记。
触及打点/事件窗口会明确提示，不删除数据库中的更早记录。
匹配器按时钟域建立时间索引，避免每条事件遍历整条长轨迹。

## 参数和导出

信令详情补齐源/目标 PCI 和 ARFCN、事务号、任务 ID、接收时间、时钟域、
采集批次和原消息关联。主信号工参中补充 RSRP、RSRQ、SINR 的实际来源，
以及服务小区观测龄期；Android 补读会单独注明，保留缺失值显示。
既有 TA、CQI、收发功率、带宽、PRB、MCS、BLER、重传、
RRC 测量配置及 NAS/IMS 参数沿用现有解码，不用未经确认的公式填空。

- 轨迹 CSV 增加任务、订阅、时钟域、定位质量列，仍可读取旧版 CSV。
- “事件 → 导出任务”生成 JSONL：任务/Mission 元数据、当前打点窗口内的该任务
  WGS84 样本、最近事件，包含是否达到读取上限的标记。
- CSV 导入只导入轨迹，不从本地同名任务偷配事件；尚未实现任务 JSONL 导入。
- 常规诊断 JSONL schema 3 带任务归属和事件窗口。沿用原身份脱敏边界：
  不输出事件自由文本详情或带设备标识的原始 Mission ID。
- 任务 JSONL 是用户主动选择的路测导出，包含坐标和小区身份；
  与脱敏诊断 JSONL 的用途不同。

## 过程事件（2026-11-27）

信令页现在把「信令」和「事件」分成两个列表。信令仍是已经解码的
RRC / NAS / IMS SIP 消息；事件是从这些消息推导的过程记录，点开可以回到
同一会话里的对应信令。定义、非结论和限制写在 `docs/PROCESS-EVENTS.md`。

这一步仍然不展示切换成功率，也不把单条 RRC Complete 或普通重建请求叫掉话。

## 当前限制与后续顺序

本轮复用既有前台采集路径。Activity 离开前台仍会 detach 打点，
Root DIAG 也保留原来的前台生命周期；“任务持续存在”不代表后台持续采集。
QMDL 原始二进制仍使用原有独立导出路径，任务 JSONL 不打包 QMDL 或完整原始信令。

下一阶段适合先做可显式停止的前台服务路测、数据缺口/丢弃计数与位置质量汇总，
再补能通过真实消息序列验证的切换/重建/注册流程状态机、失败原因分类和 KPI。
在建立完整流程证据之前，不展示“切换成功率”或把普通 RRC 重建请求叫掉话。
未拷贝 T-Phone 的反编译实现或私有库。

## 验证

- 22 项真实生产 Kotlin 路测/事件主机测试，包含 50,000 点 + 10,000 事件匹配。
- Node SQLite 执行生产建表/迁移 SQL：旧打点 v1/v2、旧测速和任务隔离四个场景。
- Android LTE 读取器 37 项、记录/显示/导出 29 项主机检查；
  信号快照故障注入和两条生产正则 ICU 编译回归。
- 新增 Android 数据库生命周期 instrumentation 用例，需设备执行。
- Release、签名/ZIP/ELF 检查的最终结果见 `RESUME-2026-11-18.md`。

主机 SQLite 与 JVM 测试不能代替 Android SQLite、Compose/百度地图交互、
4G/5G 和双卡真机验证。本机没有连接设备，也没有安装模拟器。
